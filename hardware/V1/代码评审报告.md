## 二、逐项详述

### C1 — 电池电量换算增益错误（高，须修复）【核心发现】

**现象**：`power_mgmt.cpp` 中：
```c
#define BAT_ADC_GAIN  2.0f      // 注释: "默认假设运放前为 1:1 分压, ADC 读电池电压的一半"
...
float v_adc = raw * 3.3f / 4095;     // 0~3.3V
float v_bat = v_adc * BAT_ADC_GAIN;  // v_bat = v_adc * 2.0
```
代码假设运放前端是 **1:1（0.5）分压**，故用增益 2.0 还原。

**原理图事实**（网表 `U10.1` 节点，已与 BOM 核对）：
- 电池检测为 LMV321 **单位增益电压跟随器**（U10.3=IN− 接 U10.4=OUT，增益 1×），IN+ = 分压中点。
- 分压电阻：**R34=45.3K（上，VBAT侧）、R35=110K（下，GND侧）**，BOM row20/row22 确认。
- 实际分压比 `k = R35/(R34+R35) = 110/155.3 = 0.7083`，即 **ADC 读到的是 VBAT 的 70.83%**，并非 50%。
- 正确增益应为 `1/k = 1.4118`，**而非 2.0**。

**影响量化**（代码用 2.0，正确 1.412，偏差 ×1.417）：

| 真实 VBAT | ADC 读入 | 代码算得 v_bat | 显示% | 正确% (增益1.412) |
|-----------|----------|----------------|-------|-------------------|
| 4.2V（满） | 2.975V | 5.95V→钳100% | **100%** | 100% |
| 3.7V | 2.621V | 5.24V→钳100% | **100%** | 58% |
| 3.3V | 2.337V | 4.67V→钳100% | **100%** | 25% |
| 3.0V（0%） | 2.125V | 4.25V→钳100% | **100%** | 0% |

→ **整个可用锂电区间（3.0–4.2V）电量条全部显示 100%**，电池指示完全失效（直到电压跌破约 2.97V 才骤降）。`power_mgmt.cpp` 注释本身已标注"⚠️ 须根据实际电阻网络标定该增益"，属已知未标定占位值。

**整改（已实施，2026-08-12）**：已将 `power_mgmt.cpp` 中 `BAT_ADC_GAIN` 改为由 BOM 电阻值推导的宏：
  ```c
  #define BAT_DIV_R_TOP   45.3f   // R34 上分压电阻 (KΩ)
  #define BAT_DIV_R_BOT   110.0f  // R35 下分压电阻/对地 (KΩ)
  #define BAT_ADC_GAIN    ((BAT_DIV_R_TOP + BAT_DIV_R_BOT) / BAT_DIV_R_BOT)  // ≈ 1.412
  ```
  修改后电量百分比随 VBAT 线性变化（4.2V→100%，3.7V→58%，3.0V→0%），电池指示恢复正常。
- 0%/100% 电压阈值 `BAT_V_MIN=3.0 / BAT_V_MAX=4.2` 仍是线性近似，锂电实际放电曲线非线性，如需精确可后续查表标定（非阻塞）。

### C2 — SD 卡在位检测脚 (GPIO38) 未使用（低）→ 已实现插拔检测 + UI 图标

**现象**：同前，硬件 CD 开关已布线但固件原不读取。

**整改（已实施，2026-08-12）**：
- **GPIO 初始化**：`init_hardware()` 中将 `SD_CD_IO`(IO38) 配为输入 + 内部上拉（外部已有 R6=10K 上拉到 3.3V），`SD_CD_ACTIVE_LEVEL=0` 表示插入=低电平（active-low）。若实际插座极性相反，改该宏为 1 即可。
- **插拔热管理**（`main.cpp` 主循环 block 8）：软件去抖（连续 3 次稳定采样≈60ms）后提交状态；
  - 插入边沿 → 挂载 + 扫描曲目；
  - 弹出边沿 → 停止播放 + 卸载 VFS；
  - 保留原 5s 扇区读探测作为脏拔/读错误后备（仅卸载 VFS，状态由 CD 去抖逻辑统一协调，避免坏卡时反复挂载）。
- **UI 显示**（`display.cpp`）：状态栏新增 **TF 卡图标**（青色卡片=已插入，灰色=已弹出，右上角斜切特征），插拔时弹 1.5s 瞬时提示（"已插入 TF 卡"/"已弹出 TF 卡"）；开机初始化仅置图标不弹提示，避免误报。

### C3 — 非 RTC 按键的休眠唤醒限制（信息，固件已正确处理）

**事实**：`KEY_NEXT=IO47 / KEY_REV=IO42 / KEY_FF=IO41` 非 RTC GPIO（ESP32-S3 仅 GPIO0–21 可作 ext1 唤醒源）。
**固件处理**：`build_rtc_wakeup_mask()` + `is_rtc_wakeup_gpio()` 仅把 PLAY(IO9)/STOP(IO14)/PREV(IO21) 纳入 `esp_sleep_enable_ext1_wakeup` 掩码，NEXT/REV/FF 被正确排除；且 `power_mgmt_power_off()` 主路径是 **脉冲 POW_EN(IO40) 切断电源锁存**（硬断电），ext1 仅作 deep-sleep 兜底。

**结论**：硬件限制，固件逻辑自洽，无需修改。仅提示：若设备进入 deep-sleep 兜底态，只有 PLAY/STOP/PREV 能唤醒，NEXT/REV/FF 无效——符合预期。

### C4 — MAX98357 SD_MODE 驱动方式正确，实际模式取决于硬件 R19（注意，关联原理图 H2）

**现象**：`main.cpp:788-796` 将 GPIO4 配为推挽输出并 `gpio_set_level(GPIO4, 1)` 强驱高；注释称"采样率模式选择脚须由 MCU 拉到固定电平"。
**核对**：ESP32-S3 GPIO4 **非 strapping、上电浮空**，固件主动强驱（非依赖上拉），上电到配置窗口内 SD_MODE 被 MAX98357 内部 100k 下拉置 Shutdown（静音/低耗），安全。
**关联**：SD_MODE 实际电压 = IO4 电平经外部 **R19(1M) 串联 + 内部下拉**分压（见原理图评审 H2），当前≈0.30V → 落入 `(Left/2+Right/2)` 求和单声道（即用户设计的单喇叭立体声）。**代码本身正确**，但通道模式最终由硬件 R19 决定；H2 建议将 R19 改 634k 以提升批量裕度，改后固件无需变动。

---

### C5 — SD 卡 SPI 引脚与 ESP32-S3 SPI2 默认脚巧合吻合（信息，正确）

**事实**：原理图 SD 卡 `SD_CLK=IO12 / SD_MOSI=IO11 / SD_MISO=IO13 / SD_CS=IO10`。这恰是 ESP32-S3 **SPI2(HSPI) 硬件默认引脚**。代码 `mount_sd_card()` 调 `SDSPI_HOST_DEFAULT()` 未显式 `spi_bus_initialize(SPI2_HOST, ...)`，依赖 SDSPI 内部默认脚——**因引脚恰好匹配而可用**，挂载正确。
**风险**：此处是"巧合正确"，若将来改 SD 引脚不与默认重合会失效。建议加注释说明 IO10–13 系 SPI2 默认脚，或在改版时显式初始化总线以解除隐含依赖。

---

### C6 — VOL−(GPIO0) 上电被按住的风险（注意，低风险）

**事实**：`BTN_VOL_DOWN = GPIO_NUM_0`（strapping 脚，低电平=下载启动模式）。硬件已有 **10K 外部上拉**（BOM R23=10K，已核对）保证正常上电为高。按键为瞬时拨轮，正常不会在复位瞬间按住。
**风险**：若用户在按下 VOL− 的同时触发上电（机械电源开关 SW1 与拨轮同体），GPIO0 可能在复位采样窗被拉低 → 进入 ROM 下载模式而非正常启动。
**缓解**：10K 外部上拉已大幅降低概率；如需彻底规避，可在 bootloader 阶段或硬件上加与门/延时，但属低成本设计权衡，非代码缺陷。提示知悉即可。
